# AI 游戏剧场 · 产品需求文档（PRD）

> 版本 1.0 | 2026-08-07 | 用途：开发实施依据
>
> 本文档是当前唯一开发依据。此前曾评估过"通用多 Agent 博弈编排平台"方案，已否决并不再考虑（否决理由见《可行性分析报告》）。
> 配套文档：《AI游戏剧场 · 系统设计 v0.1》（技术方案细节）、《AI游戏剧场 · 轻量方案 v1.0》（选题策略）

---

## 1. 需求背景

### 1.1 项目起源

产品唯一用户为短视频创作者本人。目标是在抖音/B站持续产出"多个 AI 大模型玩博弈游戏"的娱乐视频。该品类已被验证有流量（AI 狼人杀单条 35 万播放、AI 博弈论囚徒困境系列 2026 年 8 月爆火），但狼人杀与囚徒困境内容已拥挤，博弈论经典游戏的 AI 对战版（美元拍卖、海盗分金、最后通牒等）尚属空白。

### 1.2 项目约束

本项目对系统的真实要求只有两条：**①支持快速更换游戏（每期新游戏开发 ≤1 天）；②对局过程自动产出可直接剪辑的视频素材（后期 ≤30 分钟/期）**。任何超出这两条要求的设计（通用编排、可视化编辑器、评测统计学等）均视为过度设计，明确排除。

### 1.3 核心洞察

- 该品类的流量密码是：真实对局的不可预测性（AI 撒谎、背刺、翻车）、固定 AI 班底的连续剧感、内心独白与公开发言的表里不一。
- 创作者的剪辑水平有限，因此视频必须在**录制时接近成品**，剪辑只做取舍不做创作。
- 内容决策（人设、提示词、选题）由人负责，工程系统负责调度、记录、呈现，边界清晰。

## 2. 需求目标

### 2.1 定性目标

- 让创作者以最低工程量持续产出 AI 博弈游戏视频：新游戏开发 ≤1 天，单期后期 ≤30 分钟。
- 对局全程真实（无剧本、无人工干预结果），素材自动结构化沉淀。
- 观众体验对标同类爆款：有班底、有人设、有内心戏、有赛季积分榜。

### 2.2 量化目标

| 指标 | 目标值 | 验收方式 |
|------|--------|----------|
| 新游戏上线成本 | 复制模板文件夹后 ≤1 天跑通（含提示词调优） | 以海盗分金为第二个游戏实测 |
| 单期后期耗时 | 从对局结束到可发布成片 ≤30 分钟 | 实际制作计时 |
| 素材完备性 | 每局自动产出 JSONL 日志 + SRT 字幕 + 可录制回放，零手工誊写 | 检查产出物 |
| 单局成本 | 旗舰模型阵容 ≤$8/局；廉价模型试跑 ≤$1/局 | 成本报告 |
| 工程质量 | 以质量为前提，不设代码量上限；核心模块（llm/runner/logger）须有单元测试，正式对局前 Mock 模式回归全过 | 测试通过率 100% |

## 3. 用户与使用场景

唯一用户：创作者本人（会基本电脑操作，剪辑水平一般，可能不写代码——代码可由 AI 助手生成）。

典型工作流（一期视频的生产过程）：

1. 选择/开发游戏文件夹，在 config.yaml 中指定本期阵容与规则参数；
2. `--cheap` 模式用廉价模型试跑 1–3 局，检查流程与戏剧性；
3. 切换正式阵容跑局（可同时多跑几局备选），产出日志与字幕；
4. 打开 viewer 回放，确认精彩度，决定录完整版或高光版；
5. OBS 录制 viewer 自动导演播放；
6. 剪映导入 SRT → 一键配音 → 加音乐 → 导出发布；
7. 更新赛季积分榜（系统自动汇总）。

## 4. 功能需求

优先级：P0 = v0.1 必须；P1 = v0.2–v0.3；P2 = 按需。

### FR-1 游戏运行核心（P0）

| 编号 | 需求 | 验收标准 |
|------|------|---------|
| FR-1.1 | 游戏接口契约：每个游戏以文件夹形式实现 5 个接口函数（initial_state / visible_state / get_prompt / apply / is_terminal） | 美元拍卖、海盗分金均通过该契约运行，互不修改共享代码 |
| FR-1.2 | 通用对局循环 runner：调度回合 → 信息过滤 → 组装提示词 → 调模型 → 校验动作 → 更新状态 → 写日志 | 一局美元拍卖全自动跑完，无需人工介入 |
| FR-1.3 | 信息过滤：visible_state 控制每个玩家可见信息（全明牌游戏直通；隐藏信息游戏按玩家裁剪） | 海盗分金中身份互不泄露，日志审计可查 |
| FR-1.4 | 非法动作处理：模型返回非法动作时自动重试（带错误提示），连续 3 次失败则随机合法动作兜底并标记 | 注入非法响应测试通过；兜底事件在日志中可见 |
| FR-1.5 | Mock 模式：不调用真实 API，用预置/随机合法动作跑通整局，用于新游戏零成本验收 | 新游戏 Mock 跑通后才允许消耗 API 额度 |

### FR-2 模型接入与输出协议（P0）

| 编号 | 需求 | 验收标准 |
|------|------|---------|
| FR-2.1 | 多厂商适配：OpenAI / Anthropic / Google / DeepSeek 四类 API，统一调用接口，集中重试与限流退避 | 四个厂商各至少一个模型跑通对局 |
| FR-2.2 | 三段式输出协议：每次决策返回 {thought 内心独白, speech 公开发言, action 动作} 结构化 JSON，优先使用厂商原生结构化输出能力 | 正式对局中格式合规率 ≥99%；thought 字段完整入日志 |
| FR-2.3 | API Key 仅从环境变量读取，不写入代码、日志、任何产出物 | 全局 grep 无泄漏 |
| FR-2.4 | 成本统计：每局结束输出分模型 token 消耗与费用报告（内置可更新价目表） | 报告与实际账单误差 <20% |
| FR-2.5 | 双模式阵容：`--cheap` 全员廉价模型试跑 / `--cast official` 正式阵容录制 | 一条命令切换 |

### FR-3 班底人设系统（P0）

| 编号 | 需求 | 验收标准 |
|------|------|---------|
| FR-3.1 | personas.yaml 定义固定班底：名字、头像、性格描述、绑定模型、口头禅 | 班底 7–9 个角色，跨期一致 |
| FR-3.2 | 人设注入：每次决策提示词自动携带角色人设与对局历史记忆（滑动窗口，超预算自动截断） | 抽查提示词组装结果 |
| FR-3.3 | 赛季积分榜：跨局累计各 AI 战绩，自动生成当期结尾积分画面数据 | 连续 3 局后积分正确累计 |

### FR-4 事件日志与字幕（P0/P1）

| 编号 | 需求 | 验收标准 |
|------|------|---------|
| FR-4.1 | JSONL 事件日志：每事件含全局递增 seq、时间戳、回合、玩家、thought、speech、action、state_after 极简快照 | 日志为唯一事实来源，回放与字幕均由其生成 |
| FR-4.2 | 精彩时刻自动标记：大额跳价、淘汰、反转、表里不一（thought 与 speech 立场冲突）等事件自动打 `highlight: true` | 回放可按 highlight 跳转；抽查标记准确率可用 |
| FR-4.3 | SRT 字幕导出（P1）：发言轨 + 内心独白轨分轨导出，标注说话人（供剪映分配音色） | 直接导入剪映可用 |

### FR-5 回放页面 viewer（P0 框架 + leaderboard 模板；P1 其余模板与自动导演）

| 编号 | 需求 | 验收标准 |
|------|------|---------|
| FR-5.1 | 纯 HTML/JS 单文件，双击即用，拖入 JSONL 播放；无构建工具、无依赖安装 | 干净电脑上双击可运行 |
| FR-5.2 | 共享框架层：玩家列表（头像+状态）、发言/内心独白气泡流、时间轴播放控制（播放/暂停/2x/4x/跳转）、回合指示 | 所有游戏复用，零改动 |
| FR-5.3 | 盘面模板层：内置 leaderboard / proposal_vote / round_table / card_list 四种模板，游戏 config 声明类型并映射 state_after 字段；逃生舱 view.js 可覆盖 | 美元拍卖用 leaderboard、海盗分金用 proposal_vote，均无需写前端 |
| FR-5.4 | 9:16 竖屏布局一键切换（P1） | OBS 竖屏录制无黑边 |
| FR-5.5 | OBS 透明背景模式（P1） | 色键抠像可叠加解说画面 |
| FR-5.6 | 自动导演模式（P1）：按发言长度自动停顿；highlight 事件自动放慢 + 局部放大 + 音效；支持"只看高光"跳播 | 一次完整录屏无需人工操作 |

### FR-6 首发游戏内容（P0 美元拍卖；P1 海盗分金；P2 最后通牒）

- 美元拍卖：9 个 AI 竞拍 1 美元，价高者得、次高出价者也需付款；预算上限可配；含破产淘汰。
- 海盗分金：5–9 个 AI 依次提案分配 100 金币，半数否决则提案者淘汰；含身份/阵营变体参数。
- 每个游戏附带：2–3 套提示词模板、1 份 config 示例、Mock 测试配置。

## 5. 非功能需求

| 维度 | 要求 |
|------|------|
| 可移植性 | Python 3.11+，依赖 ≤5 个第三方库；Windows/macOS 均可运行 |
| 可恢复性 | 对局中断后从日志重放恢复，已消耗 token 不重复计费 |
| 可观测性 | 每局产出成本报告、事件数、重试次数、兜底次数统计 |
| 真实性红线 | 系统不得提供任何"指定对局结果/预写台词"的能力；剪辑环节的人工取舍不属于剧本化 |

## 6. 明确不做（范围外）

节点编辑器与可视化编排、DSL 与编译器、三层校验、模型竞技场统计学（Latin Square/置信区间）、Electron 打包、数据库、用户系统与多人协作、Web 服务化。以上属于规模化后的"平台故事"，触发条件见第 8 章。

## 7. 落地路线

| 版本 | 内容 | 工期 | 验收 |
|------|------|------|------|
| v0.0（手工验证） | 不开代码：手工复制粘贴跑一局美元拍卖并发布，验证内容方向 | 0 代码 | 首期视频发出并回收数据 |
| v0.1 | core 四件套（llm/runner/logger/personas）+ 美元拍卖 + viewer 框架与 leaderboard 盘面 | 1–2 天 | FR-1/2/3/4.1/5.1–5.3（leaderboard）全过 |
| v0.2 | SRT 导出 + 竖屏 + OBS 抠像 + 精彩时刻标记 + 自动导演 | 1 天 | FR-4.2/4.3/5.4–5.6 全过，单期后期 ≤30 分钟实测 |
| v0.3 | 海盗分金游戏（验证"1 天换游戏"）+ proposal_vote 盘面 | 1 天 | 从复制文件夹到跑通 ≤1 天实测 |
| v0.4+ | 最后通牒、吹牛骰子；round_table/card_list 模板按需补 | 按需 | 赛季制内容连续更新 |

## 8. 未来演化触发条件

平台化方向已否决，不再作为备选。若未来出现以下情况，再另行立项评估：粉丝 ≥10 万且游戏类型 ≥5 个；出现广告主/合作方定制玩法需求；开始带团队且有非程序员需要编排游戏。

## 9. 风险登记册

| 风险 | 等级 | 缓解 |
|------|------|------|
| 手工验证（v0.0）数据不佳，方向错误 | 高 | v0.0 前置就是为了先花 0 成本证伪；数据差则调整人设/剪辑风格再试，不进入开发 |
| 对局平淡缺戏剧点 | 中 | 多跑几局选素材（单局 ≤$1）；调人设增加性格反差与攻击性 |
| 模型 API 变动或限流 | 中 | 适配集中在 llm.py；多厂商互为备份 |
| 内心独白拉高成本与时长 | 低 | thought 长度限制在 100 字内；可在 config 关闭 |
| 同质化账号跟进抄袭 | 中 | 以班底人设与赛季叙事建立壁垒（内容资产无法被代码复制） |
