# AI 游戏剧场 · 系统设计 v0.1

> 2026-08-07 | 场景定位：单人创作者，快速制作"多个 AI 玩博弈游戏"的短视频
> 设计目标：①换游戏成本 ≤1 天；②每局自动产出可直接剪辑的视频素材；③以质量为前提完成需求，核心模块配备单元测试（不设代码量上限）

---

## 1. 核心设计决策

整个系统围绕一条主线设计：**对局即素材**。每跑一局游戏，系统自动产出三样东西——事件日志（JSONL）、字幕文件（SRT）、回放页面数据——剪辑师（您）拿到后直接进入剪映/OBS 流程，不做任何二次誊写。

三条不可妥协的原则：

1. **真实对局，拒绝剧本**。所有发言和决策来自模型真实输出，系统的职责是调度与记录，不是编剧。
2. **日志是唯一事实来源**。游戏逻辑、回放页面、字幕生成都从同一份 JSONL 事件日志读写，互不耦合。
3. **一个游戏一个文件夹**。新游戏 = 一个新文件夹（约 200–400 行），不修改任何已有代码。

## 2. 目录结构

```
ai-game-studio/
├── core/                    # 共享运行器，写一次，永不动（约 400 行）
│   ├── llm.py               # 多厂商 API 适配 + 重试 + 结构化输出 + 成本统计
│   ├── runner.py            # 通用对局循环：调度回合 → 组装提示词 → 调模型 → 校验 → 写日志
│   ├── logger.py            # JSONL 事件写入 + SRT 字幕导出
│   └── personas.yaml        # 固定班底：每个 AI 的名字、头像、性格、绑定模型
├── games/                   # 一个游戏一个文件夹
│   ├── dollar_auction/
│   │   ├── game.py          # 游戏逻辑（实现 5 个接口函数）
│   │   ├── config.yaml      # 本局参数：参与 AI、起拍规则、预算等
│   │   └── prompts/         # 该游戏的提示词模板
│   ├── pirate_gold/         # 海盗分金
│   └── ultimatum/           # 最后通牒
├── viewer/
│   └── index.html           # 回放页面：双击打开，拖入 JSONL 即播放（纯前端，无构建）
└── out/                     # 每局产出：YYYYMMDD_游戏名_场次.jsonl / .srt
```

技术选型：Python 3.11+（运行器），viewer 为纯 HTML/JS 单文件（双击即用，不需要 node、不需要打包）。不引入 Electron、不引入数据库、不引入前端框架。

## 3. 游戏接口契约（"满足多款游戏"的关键）

`games/xxx/game.py` 只需实现 5 个函数，runner 负责其余一切：

```python
def initial_state(config) -> dict          # 初始局面
def visible_state(state, player_id) -> dict  # 信息过滤：该玩家能看到什么（全明牌游戏直接返回 state）
def get_prompt(state, player_id) -> str    # 当前该玩家做决策的提示词
def apply(state, player_id, action) -> dict  # 校验并执行动作，返回新局面；非法动作抛异常（runner 自动重试）
def is_terminal(state) -> bool | str       # 结束判断，返回赢家或 False
```

- 全明牌游戏（美元拍卖、最后通牒）：`visible_state` 一行返回 state，单游戏约 150 行。
- 有隐藏信息的游戏（海盗分金的身份、狼人杀）：在 `visible_state` 里裁剪，约多 50 行。
- **新游戏 checklist**：复制文件夹 → 写 5 个函数 → 写 2–3 个提示词模板 → 用 Mock 模式免费跑通 → 正式录制。目标 1 天内完成。

## 4. 模型输出协议（视频素材的关键）

每次决策要求模型返回三段式 JSON（各家 API 的结构化输出能力保证格式，失败自动重试）：

```json
{
  "thought": "内心独白：它此刻的算计、怀疑、犹豫（不公开给其他玩家）",
  "speech": "公开发言：说给所有人听的话",
  "action": {"type": "bid", "amount": 1.4}
}
```

`thought` 字段是这个系统最值钱的设计：**AI 的内心戏就是视频的解说词和弹幕素材**。"GPT 嘴上说跟投，心里其实在盘算怎么套住 Claude"——这种表里不一的对照是同类爆款的流量密码，而它只需要在提示词里要求模型写出来、在日志里记下来。

## 5. 事件日志格式（素材的唯一载体）

```json
{"seq": 12, "ts": "2026-08-07T11:03:22", "round": 3, "type": "action",
 "player": "DeepSeek", "avatar": "ds.png", "thought": "Claude已经两轮没跟了，它在等我抬价……",
 "speech": "我出 1.2。", "action": {"type": "bid", "amount": 1.2},
 "state_after": {"highest_bid": 1.2, "highest_bidder": "DeepSeek", "pot": 1.0}}
```

- `seq` 全局递增，回放按它排序；`state_after` 是极简快照，回放页面无需理解游戏规则就能渲染盘面。
- 局结束自动导出 SRT 字幕（发言 + 内心独白两条轨），直接导入剪映。

## 6. 回放页面 viewer（摄影棚，两层架构 + 自动导演）

### 6.1 两层布局：通用框架 + 可插拔盘面

分析结论：不同游戏的回放页约 80% 相同，仅"盘面"区域因游戏而异。因此 viewer 分两层：

**共享框架层（写一次，永久复用）**：左侧玩家列表（头像 + 状态）、中间发言/内心独白气泡流、底部时间轴与播放控制、顶部回合指示、16:9 与 9:16 布局切换、OBS 透明背景抠像模式。

**盘面层（每游戏一个模板选择，不写前端代码）**：内置 4 种盘面模板，游戏在 config.yaml 中声明并做字段映射：

| 模板 | 适用游戏 | config 示例 |
|---|---|---|
| `leaderboard` 排行榜式 | 美元拍卖、积分榜收官 | `stage: {type: leaderboard, value: state_after.highest_bid, leader: state_after.highest_bidder}` |
| `proposal_vote` 提案表决式 | 海盗分金、最后通牒 | `stage: {type: proposal_vote, proposal: state_after.proposal, votes: state_after.votes}` |
| `round_table` 圆桌座位式 | 狼人杀、阿瓦隆类 | `stage: {type: round_table, seats: state_after.players, dead: state_after.dead}` |
| `card_list` 卡牌列表式 | 德州扑克等 | `stage: {type: card_list, community: state_after.board}` |

逃生舱：特殊游戏可在文件夹内放 `view.js`（接收 `state_after` 返回 HTML，约 50–100 行）覆盖默认模板，正常情况用不到。

### 6.2 自动导演模式（为"低剪辑成本"设计）

设计目标：**录屏即成品，剪辑只做取舍不做创作**。

- runner 跑局时自动标记精彩时刻（大额跳价、淘汰、反转、AI 表里不一名场面）写入日志 `highlight: true`；
- viewer 自动播放：按发言长度自动停顿，遇 highlight 自动放慢 + 局部放大 + 音效；
- 支持"只看高光"跳转模式：想出一期短视频版就跳着录；
- 录制流程：OBS 开录 → viewer 自动播一遍 → 停录，一刀不剪。

### 6.3 最低剪辑工作流（每期 15–30 分钟）

1. OBS 录 viewer 自动播放（整段或高光跳录）；
2. 视频拖入剪映，导入系统自动生成的 SRT（发言轨 + 内心独白轨分轨，每个 AI 固定音色标记）；
3. 剪映"文字转语音"一键配音 + 背景音乐；
4. 导出发布。

剩余的人工决策只有选题层面：这局够不够精彩、用完整版还是高光版。

## 7. 班底系统（人设一致性）

`personas.yaml` 固定 7–9 个"演员"：名字、头像、性格描述、绑定模型、口头禅。跨期保持一致——观众追的是"DeepSeek 又阴了 GPT 一次"这种连续剧感。每期视频结尾的战绩积分榜也由此自动生成。

## 8. 成本与安全

- 每局跑完打印成本报告（各模型 token 消耗 × 内置价目表）；正式录制前用 `--cheap` 模式全换 DeepSeek 级模型试跑，满意后 `--cast official` 换旗舰模型录正式版。单局旗舰成本约 $3–8。
- API Key 只从环境变量读取，绝不写入代码、日志、视频。
- 每局日志保留原始文件，翻车的局也是素材（"AI 集体犯傻"本身就是一期选题）。

## 9. 落地顺序

| 版本 | 内容 | 工作量 |

| v0.0（已完成，本周） | 手工复制粘贴跑一局美元拍卖，验证内容方向 | 0 代码 |

明确不做：节点编辑器、DSL、竞技场统计、用户系统、打包分发。这些属于"平台故事"，与出片无关。

## 10. 风险与边界

- 模型 API 变动/限流：llm.py 集中处理，换厂商只改一个文件。
- 某局对局平淡无戏剧点：这是内容问题不是系统问题——多跑几局选素材（成本极低），或调人设 prompt 增加攻击性/性格反差。
- 您不打算自己写代码的情况：全部代码可由 AI 助手生成并提交至 GitHub，您只需会安装 Python、配置环境变量、双击运行；核心模块附带单元测试。
